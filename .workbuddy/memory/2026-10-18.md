## 服务端 TTS 落地（用户说「太机械」后选定的方案）

链路：进题目时后端按需生成 MP3 → 前端 `<audio>` 播 → 播不动就退回 iOS 内置朗读。
**音质用微软 XiaoxiaoNeural，且因为是真音频，锁屏/后台能听了**（内置 TTS 做不到这条）。

### 引擎选型（都实测过）
- `edge-tts-universal`：**卡死**，不要用它（Universal API 走 Node 全局 WebSocket，搞不定微软要求的自定义头）。
- **`node-edge-tts` 可用**（48 字 → 60KB MP3）。依赖 ws/https-proxy-agent/yargs，纯 JS，符合零原生编译。
  构造参数：`new EdgeTTS({ voice, lang, outputFormat, rate, pitch, volume, timeout })`，默认 timeout 只有 10s，要调大。
  注意：不是所有包都能跑通，**必须先写探针脚本实测再决定**。
- 备选：Python `edge-tts`（本机 venv 里已装，能跑，但部署是 Node 项目，没用它）。

### 实测数据（本地 / 线上）
- 题目 ~18 字：本地 1.0s / 25KB；线上首次 2.2s
- 答案 ~550 字：本地 2.0s / 632KB；线上首次 7.5s
- 缓存命中：本地 0.011s，线上 0.56s
- **线上沙箱确认能联网调微软**（本次最大风险点，已验证通过）

### 代码
| 位置 | 职责 |
|---|---|
| `server/tts.js` | 按需生成 + `data/tts/` 文件缓存 + 300MB LRU（命中刷 mtime）+ 同 key 并发去重 |
| `server/routes/tts.js` | `GET /api/tts/:seq/:part`（part=q/a）；题不存在 404、生成失败 503 |

### 三个必须记住的约束
1. **必须预取，不能点了再下**：iOS 上 `<audio>` 首次出声同样要在用户手势的同步栈里，
   await 完再 play 会静默失败。所以进题目就后台拉好（当前题 + 下一题），点开关时同步 play。
2. **音频缓存会吃内存**：答案 600KB/段，一路背下去几百 MB。进背诵页 `resetServerAudio()` 清一次
   （HTTP 缓存还在，重背不用重下）。blob 缓存是模块级单例，**测试间会串味**。
3. **`data/tts/` 不能留在本地**：发布会把 `data/` 一起上传。本地测完必须删。

## 二轮反馈：电脑上能听到 Xiaoxiao，iPhone/iPad 却是 Siri —— 根因与修复

**用户自己的诊断是对的**：「阅读前，xiaoxiao 的语音并没有被合成出来」。
即点开关那一刻音频还没生成完，于是走了本机朗读。三个原因叠加：

1. **要求题目+答案两段都到齐才用服务端音频**（主因）。答案线上首次要 7.5 秒，
   用户点开关时它几乎不可能就绪 → 整张卡退回内置 TTS。
   ✅ 改成：题目一到就播（约 1-2 秒），答案后补。
2. **连续失败 2 次就判死整场会话**（`FAIL_LIMIT`）。iOS 上网络抖一下就会永久退回本机朗读。
   ✅ 直接删掉这个禁用机制，每题都重新试；失败的请求返回很快，代价可接受。
3. **用 blob URL 当 audio src**。iOS 对 blob 音频支持不稳，且 blob 常驻内存（600KB/段）、锁屏后可能放不出。
   ✅ 改成**真实 URL** `/api/tts/:seq/:part` + HTTP 缓存（`Cache-Control: private, max-age=604800`），
   预取只负责把响应塞进浏览器缓存（`warmSegment` 读完 `arrayBuffer` 才进缓存，这点很关键）。

另外两处体验修改：
- **停顿 3 秒 → 1.5 秒**（用户嫌长），且**答案音频在题目一开始就并行下载**，
  不再「播完才等」——否则停顿时长 = 下载时间 + 停顿。
- 新增**「连播」开关**（`recite.autoNext`，只在自动阅读打开后显示）：一整张卡念完自动翻下一题。
  - `speech.ts` 的 `play()` 加了 `onDone`（整段念完回调，被 stop 打断不回调）；`cardAudio` 同样有 `onDone`。
  - ⚠️ **闭包陈旧坑**：`onDone` 在开播那一刻捕获 state，用户播到一半才开连播 → 读到旧的 `false`。
    必须用 ref 读最新值（`autoNextRef` / `goNextRef`，在每次渲染的 effect 里更新）。

UI 上加了**音源指示**（开关左侧小字：「云端音质」/「本机朗读」）——
没有它，「听着还是机械的」根本无从判断问题出在哪。**这类可观测性以后要主动加。**

单测 182 条全绿、`typecheck` 过。已部署，bundle `index-qrOHQk8M.js`。
线上进度已到第 42 题（用户在真用，一次比一次深）。

## 停顿调成 400ms（用户：「基本不要停顿吧」）

`PAUSE_BEFORE_ANSWER_MS` 3 秒 → 1.5 秒 → **400 毫秒**。
留 400ms 只是防两段音频首尾粘连（完全为 0 会听成一句话），不再承担「留时间回忆」的职责。
⚠️ 改这个常量时，`cardAudio.test.ts` 里显式写 pauseMs 的用例要跟着改，否则推进的定时器对不上。
