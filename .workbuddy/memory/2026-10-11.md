PDF 在 `pdf/Java 热门面试题 200 道速记通关版 面试刷题 mianshiyacom.pdf`（33MB，130 页，**有文本层**，非扫描件 → 不需要 OCR）。

**切题规则（关键，别再重新推）**：题干行字号 **9.65**、正文 **8.25**、封面 16.5。字号 9.65 的行**恰好 200 行**，与书名「200 道」吻合。

**两个已修的坑**：
1. 子集字体 `ToUnicode` 映射错误，5.18% 汉字落在「康熙部首区 U+2E80–U+2FDF」（⽤⼀⾯…）。修法：康熙部首用 NFKC，其中 14 个「C-simplified」（见长风门页骨马车贝飞鱼鬼角）Unicode 无兼容映射，查表硬编码。函数 `normalizeRadicals()`。
2. 行必须攒齐后再取文本，否则每行只剩第一个字（第一版在行创建时就快照了）。
3. 附带：`detectBodySize()` 必须用**众数**（字符数最多的字号桶），不能用加权平均——样本少时平均值被题干拉高，ratio 掉到 1.06 会漏判。

产出：`web/src/lib/pdf/parse.ts`（纯函数，13 单测）、`scripts/extract-questions.mjs`、报告 `pdf-parse-report.md`。
**Node 22 可直接跑 `.ts`**（类型擦除），所以 Node 脚本和浏览器共用同一份解析源码，不会漂移。

## P3 完成：背诵模式

- `server/routes/progress.js`：`GET/PUT/DELETE /api/progress`
- `web/src/pages/Recite.tsx`（`/recite`，ued.md S4）：题答同屏 + 顺序/随机 + 上/下一题 + 左右滑动 + 顶部细进度条

- `pages/Bank.tsx` 加了「重置背诵进度」（行内二次确认）

**四条设计决定（改之前先看这里）**：
1. **位置语义是「已背题数」，取值 0..N，不是数组下标**。取到 N 表示这一轮背完了 —— 否则「已背 240/240」没法表达。服务端 `clamp` 也必须允许取到 total。
2. **顺序与随机各存一个位置**（`posOrder` / `posRandom`）。这是 ued「切到随机记住当前位置、切回顺序可继续」的前提；只存一个 position 一切换就顶掉。
3. **随机序列 `randOrder` 也存服务端**。否则刷新会重洗，就做不到「刷新停在同一题」。再点一次「随机」= 换一批。
4. **题库规模一变，位置一律归零**：换题库后旧位置指向别的题，比丢掉更糟。

**踩坑**：
- **写进度必须串行化**（Promise 链）。连点下一题会并发发出 PUT，网络乱序会让位置回退。
- `progress` 表从「一行三字段」改成「一行 JSON」，靠 `PRAGMA table_info` 检测旧结构后 `DROP` 重建（P3 前没写入过真实进度，重建不丢东西）。
- **`npm run build` 之前只跑 `vite build`，完全没有类型校验**（esbuild 只剥类型不检查）。补上 `tsc --noEmit` 后冒出 4 处 P0/P2 埋下的真错误：
  ① pdfjs v6 类型里已无 `isEvalSupported`；② `getTextContent().items` 是 `TextItem | TextMarkedContent` 联合类型，取 `.str` 前必须先 `'str' in it` 窄化；
  ③ `parse.ts` 里 `CJK` 是死代码；④ **`Import.tsx` 的 `stage` 判断漏了 `'saving'`** —— 一点「确认入库」整块 DOM 就卸载，界面闪回选文件页，「入库中…」永远看不到（真 bug，不是纯类型问题）。
- e2e 文案断言会随首页改动过期：`共 200 题` → `已背 0 / 200`。**改首页文案记得同步 e2e。**
- `login.spec.ts` 的「深链接刷新」原来用 `/recite`，P3 之后它成了真实路由、不再走 SPA 兜底 → 换成不存在的路径。
