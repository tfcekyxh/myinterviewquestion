## P0 完成：PDF 解析验证通过（准确率 100%）

PDF 在 `pdf/Java 热门面试题 200 道速记通关版 面试刷题 mianshiyacom.pdf`（33MB，130 页，**有文本层**，非扫描件 → 不需要 OCR）。

**切题规则（关键，别再重新推）**：题干行字号 **9.65**、正文 **8.25**、封面 16.5。字号 9.65 的行**恰好 200 行**，与书名「200 道」吻合。
- 不能按题号切（PDF 里没有编号）、不能按页切（答案跨页）、不能按空行切（空行只在换页处）→ **只能靠字号台阶**。
- PDF 是**逐字形绘制**的，同行的 y 有抖动，聚行必须给 1.5 容差。

**两个已修的坑**：
1. 子集字体 `ToUnicode` 映射错误，5.18% 汉字落在「康熙部首区 U+2E80–U+2FDF」（⽤⼀⾯…）。修法：康熙部首用 NFKC，其中 14 个「C-simplified」（见长风门页骨马车贝飞鱼鬼角）Unicode 无兼容映射，查表硬编码。函数 `normalizeRadicals()`。
2. 行必须攒齐后再取文本，否则每行只剩第一个字（第一版在行创建时就快照了）。
3. 附带：`detectBodySize()` 必须用**众数**（字符数最多的字号桶），不能用加权平均——样本少时平均值被题干拉高，ratio 掉到 1.06 会漏判。

产出：`web/src/lib/pdf/parse.ts`（纯函数，13 单测）、`scripts/extract-questions.mjs`、报告 `pdf-parse-report.md`。
**Node 22 可直接跑 `.ts`**（类型擦除），所以 Node 脚本和浏览器共用同一份解析源码，不会漂移。

## P1 完成：Express + SQLite 骨架与登录

- `web/`：Vite + React 19 + BrowserRouter；登录页按 ued.md S0；CSS Variables 映射设计令牌
- 验证：接口级 `scripts/smoke-auth.mjs` 11/11；组件测试 5；Playwright e2e 5（含刷新不掉线）

**新踩的坑**：
- **Express 5 的 path-to-regexp v8 不支持 `'*'`**，SPA 兜底必须写 `app.get('/*splat')`，否则启动直接抛 `PathError: Missing parameter name`。
- **`<label>` 不能把「显示密码」按钮包进去** —— 输入框的可访问名会变成「密码 显示密码」，Playwright `getByLabel('密码')` 会同时命中两个元素报 strict mode violation。改用 `htmlFor` + `id` 显式关联。
- **本机 curl 走代理**，连 `127.0.0.1` 也返回 502 "upstream connect failed"。接口验证改用 node 的 fetch（或 curl 加 `--noproxy '*'`）。
- 服务端启动时若 `web/dist` 不存在会注册 503 分支，构建后必须重启服务。
