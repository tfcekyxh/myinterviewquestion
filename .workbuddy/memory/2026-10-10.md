## 同日再追加：测试策略（tech-stack.md 第十一节，已实测）

用户定：**React Testing Library 做 component test，Playwright 做 e2e。** 三层验证：

- **L1** Vitest 5 + RTL 16 + jsdom 30（React 19）→ 已跑通 **4/4**
- **L2** Playwright 1.64（Chromium + 假麦克风）→ 已跑通 **2/2**，含 iPhone 13 视口(390×844)
- **L3** 真机 iPhone Safari 手动清单 5 项 —— **不可省**，Playwright 跑不出真 iOS Safari（macOS WebKit ≠ iOS Safari）

实测版本：vitest 5.0.3 / vite 8.3.4 / jsdom 30.1.2 / @testing-library/react 16.3.3 / jest-dom 7.0.1 / user-event 14.6.7 / @playwright/test 1.64.0。全部零 node-gyp 编译。

### 实测出来的硬结论（别再重查）
- **jsdom 里没有 `MediaRecorder`，也没有 `navigator.mediaDevices`**（实测 undefined）→ 录音逻辑**必须抽成 `src/lib/recorder.ts` 接口**，组件测试用 `vi.mock` 换桩，真录音只在 e2e 里跑
- **Chromium 的 MediaRecorder 选的是 `audio/mp4;codecs=opus`，不是 webm** → **录音文件扩展名绝不能写死 `.webm`**，必须按 `recorder.mimeType` 推导（iPhone 出 audio/mp4）
- 组件测试最该锁的是 ued.md 那条硬约束：**对照答案前，整个 `document.body.textContent` 都不能出现答案文本**

### Playwright 四个真踩到的坑
1. `devices['iPhone 13']` **默认把浏览器切成 WebKit** → 必须在 `...devices` 之前显式写 `browserName: 'chromium'`，否则报 webkit 未安装
2. 项目 `package.json` 有 `"type": "module"` → 服务端 `.js` 用 `require` 会报 `require is not defined`，服务端文件用 `.cjs` 或改 ESM
3. `webServer.url` 探测根路径，**404 也算未就绪**，会干等到 timeout
4. 浏览器 build 版本要与 Playwright 版本匹配（缓存 1243 vs 1.64 要 1248）

### 本机环境问题（重要）
`npx playwright install` 一直报 `EEXIST: __dirlock`。原因：`~/Library/Caches/ms-playwright/__dirlock` 有个 **10-04 留下的陈旧空锁目录**。**已用 `rmdir` 清掉**（只对空目录生效）。以后再遇到同样报错就是同一原因。chromium-1248 下载仍在进行中（VPN 已开）。

## 同日追加：技术栈 v2（推翻 v1）

用户补充两个关键约束：**① SQLite 上线就用，不是临时方案 ② 后端是 Express，登录方案不喜欢，要另推荐。**

架构因此从「纯静态 + 浏览器内 SQLite + 云服务 Auth」改为：
**iPhone Safari → Express（单端口，同时托管 Vite dist 与 /api）→ SQLite 文件（node:sqlite）**

> v1 记录保留在下方可作历史参考；**实施以 v2 为准**。

### 核心选型原则：依赖必须零原生编译
发布沙箱只有一个 HTTP 端口、没有 C/C++ 工具链，需要 node-gyp 的包很可能让部署直接失败。据此淘汰：
- `better-sqlite3` / `sqlite3`（原生模块）
- `connect-sqlite3` —— **我拆包查过**：package.json 里没声明依赖，但源码 `require('sqlite3')`，隐性引入原生模块
- `bcrypt` / `argon2`（原生编译）

改用 Node 内置：`node:sqlite`（数据库）+ `crypto.scrypt`（密码哈希）。

**node:sqlite 实测结论**：Node **22.22.2 可直接 `require('node:sqlite')`，无需 `--experimental-sqlite` flag**（仅有 ExperimentalWarning）。23.4+ 也不需 flag。

### 登录方案（已端到端跑通验证）
`express-session` + **自写 SqliteStore（40 行，复用主库）** + `crypto.scryptSync` + `crypto.timingSafeEqual`。
实测结果：错误/未登录 401、正确 200 且 Set-Cookie 带 HttpOnly、鉴权通过、session 落 SQLite。
不推荐 JWT（`jose`，单用户过度设计）与 Passport（为多策略设计，白付复杂度）。

**部署必加 `app.set('trust proxy', 1)`** —— 不加则 HTTPS 下 secure Cookie 不下发，症状是「登录成功但刷新就掉线」，极难排查。

### Express 组合约束
单端口托管一切，路由顺序不可颠倒：`/api` → `express.static(dist)` → `app.get('*')` 兜底。
因此前端**可以用 BrowserRouter**（有自己写的 fallback，不再被迫 hash 路由）。
启动必须 `app.listen(process.env.PORT, '0.0.0.0')`。

### 两个已消失的旧问题
iOS 7 天清存储、换设备丢进度 → 数据在服务端，都不存在了。决策 5「跨设备接着背」重新成立。
自建登录后**不再需要 WorkBuddy 云服务**（已开通，留着不占配额）。

### 唯一未验证项（项目当前最大技术风险，仅次于 PDF 解析）
**重新发布后 SQLite 文件是否还在。** 发布环境明确支持 SQLite、且明确不支持 MySQL/PG/Redis，但没保证磁盘持久。
兜底：加「导出/导入题库 JSON」入口。验证方式：上线 → 导入题库 → 再发布一次 → 看数据还在不在。

## 产出 `tech-stack.md`（技术栈方案 v1，已被上方 v2 取代）

用户追加约束：**数据库先用 SQLite，后续迁移到云数据库。** 据此定了整套选型。

**主方案**：纯静态前端 + 浏览器内 SQLite WASM + 云服务只做登录（Auth 仍走 WorkBuddy 云服务）。

### 选型
- 构建 Vite + TypeScript；UI React 19 + TSX
- 路由 **必须 HashRouter**（静态托管无 history fallback，BrowserRouter 刷新必 404）
- 样式原生 CSS Variables + CSS Modules，不引 UI 库（ued.md 令牌已定死，引库等于再来一套令牌）
- DB `@sqlite.org/sqlite-wasm` + **`opfs-sahpool` 后端**（见下方关键结论）
- Auth `@tencent-ai/workbuddy-cloud-sdk@dev` → `cloud.auth`
- PDF `pdfjs-dist` + `getTextContent()`（只抽文本层，不渲染 canvas）
- 录音 MediaRecorder（iOS 出 audio/mp4 AAC）+ Blob 存 IndexedDB
- 波形 AnalyserNode；轻量键值 idb-keyval

### 两个查证出来的关键结论（重要，别再重查）
1. **官方 SQLite WASM 的两个 OPFS 后端**：`opfs` 依赖 SharedArrayBuffer，**需要服务端发 COOP/COEP 响应头**（静态托管通常改不了）；`opfs-sahpool` **不需要任何响应头** → 本项目选后者。限制：同时只允许一个连接，第二个标签页打开同一库会失败，须给明确提示。
2. **iOS Safari 7 天清理规则**：连续 7 个 Safari 使用日无交互，会清掉该站全部脚本可写存储（IndexedDB / OPFS / localStorage）。**添加到主屏幕的 Home Screen Web App 豁免** → 所以要加 `manifest.webmanifest` + `apple-mobile-web-app-capable`，并建议提供「导出题库 JSON」兜底。

### 为迁移留的三条硬约定
1. 数据访问只走 `src/data/repo.ts`，业务层不 import sqlite-wasm 也不 import cloud SDK
2. **所有 repo 方法从第一天起就是 async**（今天 SQLite 同步、明天是网络请求）
3. SQL 只写两边交集：INSERT 不写主键、时间存 epoch 毫秒整数、避免 JSON 列 / INSERT OR REPLACE / ON CONFLICT / AUTOINCREMENT
