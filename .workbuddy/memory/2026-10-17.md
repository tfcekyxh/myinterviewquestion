## 新增：背诵页「自动阅读」（TTS 朗读）

需求：背诵时自动念题目和答案。先做了三轮澄清，用户定的三个决策：

用户另外想要「锁屏/后台能听」，但**这与内置 TTS 互斥**，已讲清并同意本次不做，
方案写进 `project-scope.md` 五、暂缓（要后台只能服务端预生成 MP3 + `<audio>` + MediaSession）。

## 实现

- 新文件 `web/src/lib/speech.ts`：TTS 全部逻辑都在这。
  - `splitForSpeech()` 切段（Chrome 超 ~200 字会掐断；优先在标点断，无标点才硬切）
  - `segmentsForCard()` 纯函数编排：题目段… + `{pauseMs}` + 答案段…（缺一半时不插停顿）
  - `pickVoice()` 选中文音色：精确 `zh-CN` → 同语种前缀 → null（交给 `utterance.lang` 兜底）
  - `createSpeaker()` 队列播放器，`play/stop`
- `Recite.tsx`：顶部进度过下方一个 `role="switch"` chip，状态存 localStorage `recite.autoRead`。

## 三个 iOS 硬约束（写代码时绕不过去，改这块前必看）

1. **首次 `speak()` 必须在真实点击的同步调用栈里**，否则静默失败（连 setTimeout 都不行）。
   → 开开关的那次点击里**同步**调 play，绝不能交给 `useEffect`。
2. **记住的开关刷新后不能自动播**：那条路径同样不在手势栈里，播了也不响。
   → 加了 `speechArmed` 状态：localStorage 记住 true 时，注册一次性 `pointerdown` 监听，
   用户第一次碰屏幕时**在监听回调里同步念第一句**完成解锁，之后 `useEffect` 才能接管翻题自动播。
3. **连播约 15 秒会被系统自动暂停** → 每 9 秒 `pause()/resume()` 心跳保活，**只在 `speaking && !paused` 时做**
   （空闲时 pause 会把还没开始的队列一起冻住）。另外 utterance 必须**全程持有引用**，否则被 GC、`onend` 永不触发。

其余无法绕开的限制：静音拨片打开时无声且无任何 API 可检测；锁屏必停。

## 用户反馈「声音太机械」→ 查因 + 改进 + 二次部署（17:00）

**先查了全量换 TTS 的可行性，结论是不行**：题库 11.4 万字（题目平均 19 字、**答案平均 553 字**，
最长一题 1053 字）→ 全量转音频约 **424 分钟 / 99 MB**，上传和存储都不现实。
（统计用的就是 `data/app.db`，一句话脚本见 `/tmp/stats.mjs` 思路：`node:sqlite` 数 `questions` 字符数。）
顺带说明：答案念完要 2 分钟，这个节奏本身也值得怀疑。

**真正的元凶是两个 bug，已修**：
1. **iOS 的 `getVoices()` 首次常返回空数组**，而我只在播放那一刻同步取一次 → 一个中文音色都挑不到
   → 系统拿默认音色（很可能是英文的）去念中文，听起来格外怪。
   现在进背诵页就 `primeVoices()` 预热 + 监听 `voiceschanged` 补货 + 模块级缓存。
2. **没优先挑「增强版」音色**：系统自带的紧凑版很机械，用户手动下载过的增强版（接近 Siri）好得多。
   `pickVoice()` 改成分打分：语言精确匹配 100 分 > 增强/高级/premium/neural 音色 50 分 > localService 1 分。
   ⚠️ 增强音色**不能跨语言**优先（用 zh-TW 念简体音调是错的）→ 语言分必须压过增强分。

单测 162 条全绿（新增 3 条）。已二次部署，线上 bundle `index-BKqFKaFe.js`，数据 200 题不变。

⚠️ 测试踩坑：音色缓存是**模块级单例**，会被上一个用例污染 → `beforeEach` 里要调 `primeVoices()` 重读。
为此 `primeVoices()` 设计成**每次调用都强制重读**（voiceschanged 回调里才保留旧值）。
`addEventListener` 的回调必须是**具名常量**（`onVoicesChanged`），否则重复注册，且测试里拿不到监听器。
