# 项目长期记忆：myInterviewQuestion

## 项目目标
把一份本地题库 PDF，转成可在手机上翻卡复习的题目卡片。用户是备考者本人，痛点是「PDF 里的题目没法一道一道地刷」。

**用户设备：只用 iPhone。** 这是所有兼容性决策的第一约束（也因此才敢用 iOS Safari 自带的语音识别）。

## 已确认的需求决策（2026-09-29）
| 维度 | 结论 |
|---|---|
| 形态 | 手机 H5 网页（免安装，数据存浏览器本地，**无后端**） |
| 题目来源 | 用户自己提供题库 PDF，按实际排版定解析规则 |
| 卡片形式 | **题答同屏**（题目和答案一起显示，不翻面） |
| 背诵顺序 | 顺序背（保留原序，含层层递进题目）+ 随机背（打乱抽查） |
| 进度 | 记住背到哪一题，下次接着背 |
| 复习模式 | 答案隐藏 → 对着题目**开口讲并录音** → 点开答案自己对照；同样支持顺序/随机 |
| 录音 | 复习时录音，**只保存到手机本地 + 可回放**；不做语音转文字（暂缓，见下） |
| 复习入口 | 首页**独立入口** |
| 复习范围 | 用户页面上自选：刚背完的一轮 / 整个题库 |
| 登录 | **单一账号**（提前预设、**无注册流程**），打开网页需输入账号密码才能进；进度与录音仍存本机，**换手机登录不同步** |
| 明确不做 | 按章节分组选范围、错题清单、**注册流程 / 多账号 / 多端同步**、语音转文字（暂缓） |

## 已查清但本期不做的：语音转文字（用户决定暂缓）
路线：**iPhone 上可用 iOS Safari 自带的 `webkitSpeechRecognition`**（Safari 14.1 / iOS 14.5+），免费、无后端。
硬条件：必须用 **Safari 打开**（微信等 App 内置浏览器会报 `service-not-allowed`）、必须 **HTTPS**、必须**联网**（音频会上传 Apple）、需授权麦克风与语音识别。
限制：**只能实时听麦克风，不能转写已有录音文件** → 录音与转文字必须同时进行。
结论全文保存在 `project-scope.md`「五、暂缓 / 后续版本」。**想启用时第一步是做个极简真机验证页（录音 + 实时转文字），在 iPhone Safari 上跑一次。**

## 已知风险
- **风险一：PDF 解析准确率。** 产品能不能用的前提。若是扫描件（无文本层）需额外做 OCR。
- 录音功能本身风险很低：只是调用麦克风录音存本地，iOS Safari 原生支持。
- **登录只能做到「自家门锁」级别。** 无后端 → 账号密码校验只能写在前端代码里，懂技术的人翻源码即可绕过。能挡随手点开的人，挡不住刻意破解。要真正安全或要跨设备同步进度，就必须加后端。
- 题答同屏缺少主动回忆环节，但**复习模式正好弥补**（隐藏答案 + 开口复述）。
