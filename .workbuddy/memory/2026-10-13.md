启动项目后按 impl-plan 的 P5 继续，四项任务全部落地：

1. **网络失败提示**（`web/src/lib/api.ts`）
   - fetch 的 reject（断网 / 服务挂了）原本抛英文 `TypeError`，被页面直接当文案显示 → 统一换成 `NET_ERROR_MESSAGE`
   - 反向代理回 HTML 时 `JSON.parse` 会炸 → 兜住，5xx 给「服务器出错了，稍后再试」
2. **401 语义分流**（`api.ts` + `lib/session.ts`）
   - `/api/me` 的 401 = 未登录（探活）/ `/api/login` 的 401 = 密码错 / **其他接口的 401 = 登录态过期** → `setUnauthorizedHandler` 踢回登录页
   - 不区分会死循环：登录页 401 → handler → 再探活 → 又 401
3. **PWA**：`web/public/manifest.webmanifest` + `icon-{180,192,512}.png` + index.html 的 link/meta
   - 图标是 `scripts/gen-icons.mjs` 生成的（纯 Node 的 PNG 编码器：zlib + CRC32，4 倍超采样），
     因为环境没有图像库，而 iOS 的 apple-touch-icon 只认 PNG
4. **测试**：新增 `web/src/lib/api.test.ts`（6 条）+ `e2e/pwa.spec.ts`（3 条：资源、深链接、断网提示）

## 整库导出 / 还原（用户要求：能导出数据库源文件、再导入回去）

- `server/routes/backup.js`：`GET /api/backup` 下载整个 SQLite 文件（`VACUUM INTO` 做一致性快照）；
  `POST /api/restore` 上传 .db 整库还原（raw body，`express.raw`，不能走全局 `express.json`）
- `server/db.js`：`db` 改成 `export let` + `closeDb()` / `reopenDb()`，靠 ESM live binding 让各路由拿到新连接
- 前端：`api.ts` 加 `downloadBackup()` / `restoreBackup(file)`；`/bank` 页加「数据库备份」区，
  还原是覆盖全部数据的操作，所以**必须过二次确认**
- 还原顺序：先验文件（文件头 / 缺表 / 真读一次）→ 关连接 → 旧库改名 `.bak` → 落新文件 →
  清 `-journal/-wal/-shm` → 重开；任一步失败回滚 `.bak`。还原后把 session 写回新库，不掉线
- **顺带修的产品问题**：换题库（`POST /api/questions`）现在连复习记录一起删 ——
  复习记录记的是 `question_id`，题一换就指向空气，「复习过几题」会一直显示错数字
