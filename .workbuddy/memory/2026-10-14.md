## 部署前评估（用户问「还需要做什么，能直接部署吗」）

结论：**架构上没有硬阻塞**（Express + SQLite 单端口正是发布沙箱支持的形态，
沙箱不支持 MySQL/PG/Redis，我们一个都没用）。但部署前有三件事必须先处理：

1. **环境变量是最大卡点**：`.env` 不在 git 里，上传时大概率不会带上 →
   线上没有 `APP_ACCOUNT` / `APP_PASSWORD` / `SESSION_SECRET`，
   `ensureUser()` 会报错、`process.exit(1)`，服务根本起不来。
   方案：用 `startCmd` 注入这三个变量。
   ⚠️ `SESSION_SECRET` 尤其不能省 —— 不设就用固定的 `dev-only-insecure-secret`，
   公网环境下别人能伪造 session cookie。
2. **前端产物**：`dist/` 在 `.gitignore`，沙箱只 install + start，不一定跑 build →
   `startCmd` 必须带上 `npm run build`，否则首页就是 503「前端尚未构建」。
3. **数据是空的**：线上是全新库，要靠刚做的整库还原（传 .db）或重新导入 PDF。

部署的额外收益：公网 HTTPS → 手机**不用再装自签证书、不用和电脑同一个 Wi-Fi**，
录音随时可用（Safari 只在安全上下文给麦克风权限）。

顺带能验掉最后一个风险点：重新发布一次，看 SQLite 数据还在不在。

**用户决定：线上换一个专用密码（和本地不同）** —— 等他确认密码后再发布。

## 录音持久化（下午，用户问「想保存录音呢」）

### 起点：用户质疑「离线回听在哪」，质疑对了
之前给用户画的方案图里，我写「现状 = ✓ 离线随时能回听」—— **这句是错的**。
grep 后确认：`audioStore.ts` 里 `loadClip` / `clipStats` / `deleteClip` **全是死代码**，
全项目只有 `saveClip` 被调用过。后果是录音进了 IndexedDB 就再也读不回来，
回放条只在「刚录完 → 对照答案」那一屏活着，点「下一题」被 `clearClip()` 清掉即失忆。
→ **教训：给用户的现状描述要grep验证，别凭印象写「✓」。**

### 用户拍板：单条保存 + 批量导出
三条路（本机/导出到文件App/云端对象存储）里否掉了「传自己 Express 的 data/audio」——
每次重新发布会用本地 data/ 覆盖线上，SQLite 持久性都还没验，音频更靠不住。

### 改动
- `web/src/lib/clipExport.ts`（新）：交给系统的那一层。Web Share Level 2（iOS 15+）优先，
  不支持降级 `<a download>`。`formatBytes` / `formatClipTime`。12 条单测。
- `web/src/pages/Clips.tsx`（新）：「我的录音」页 —— 列表 + 回听 + 单条导出/删除 + 全部导出
  （带进度与停止）。13 条单测。
- `web/src/lib/audioStore.ts`：加 `listClips()` / `seqOfClip()`。
- `web/src/pages/Review.tsx`：对照答案屏加「保存这段录音」。
- `web/src/App.tsx` 加 `/clips` 路由；`web/src/pages/Home.tsx` 把「开始复习」与「我的录音」并排一行（不增加垂直堆叠）。

### 关键设计决策
1. **题号不新加字段**，一律 `seqOfClip()` 从 key（`clip:${seq}:${ts}`）反解 ——
   线上已有的一批录音没有 seq 字段，反解才能新老数据走同一条路，免做迁移。
2. **立刻 revokeObjectURL 会掐断还没开始的下载**（iOS 表现「点了没反应」）→ 延后释放。
3. **`<audio>` 换 src 后 autoPlay 不会再触发**，必须自己在 effect 里 play()。最初只写属性，
   结果只有第一段能响 —— 写页面时发现修掉。
4. **拿不到题库（网络挂了）照样列录音**，只是不显示题干。录音在本机，不该被服务端故障挡门外。
5. 批量导出前明确告知「会依次弹出 N 次分享面板」（iPhone 一次只能存一个文件），避免用户以为卡死。

### 顺手揪出的两个隐蔽大坑（都不是这次改动引入的）
1. ⚠️ **`.gitignore` 第 14 行 `pdf/` 吞掉了 `web/src/lib/pdf/`**：不带前导斜杠、又以 `/` 结尾的
   ignore 模式会匹配**任意层级**同名目录 → P0 切题算法（`parse.ts` + `extract.ts` + 13 条单测）
   **从未进过版本库**。换机器/新 worktree 时 PDF 导入直接消失、typecheck 与 build 全红。
   当初部署没炸只是因为发布工具上传本地文件、不走 git。
   已改成 `/pdf/`，并从主仓把三个文件捞回来纳入版本控制。**加 ignore 目录规则一律写 `/xxx/`。**
2. ⚠️ **干净 checkout 跑 e2e 的前置条件缺失**：e2e 直接起 Express 托管 `web/dist`，
   dist 不在 git 里 → 服务返 503「前端尚未构建」→ `webServer.url` 探针把非 2xx 当未就绪 →
   报毫无指向性的 `Timed out waiting 60000ms from config.webServer`。另外缺 `.env` 服务会 exit 1。
   两条都已写进 `CLAUDE.md` 的测试约定与命令节。
